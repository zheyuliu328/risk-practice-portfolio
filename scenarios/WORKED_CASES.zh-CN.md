# 从计算结果到工作交付

这里的企业、交易和数字均为独立虚构。目标是完成一次可复核的分析任务，不是模拟已经获得业务授权。先读对应[场景协议](README.md)，再执行下列请求；输出目录每次使用新名称。

```sh
risk-practice --input examples/broker-margin.json --output outputs/margin-review-01
```

打开输出中的 `report.html`，将 `request.json`、`result.json`、`manifest.json` 一起保留。报告包含输入和逐行证据；校验和只能发现字节变化，不能证明来源真实。所有金额须使用同一币种和单位；时间单位由各模型明确指定，不自动换算。

## 可执行任务与处置

| 场景 / 请求文件（均在 examples 下） | 要解决的工作问题 | 检查点与应对方案 | 交付对象 |
| --- | --- | --- | --- |
| C01 / credit-parameters.json | 模型区分能力不错，是否可以接受？ | 示例成熟样本 AUC .875、Brier .145；先核对未成熟和缺失标签排除，再看分组校准。不能凭 AUC 批准部署；校准不足时分群调查或重新校准，再独立验证。 | 信用模型负责人、独立验证 |
| C01 / recovery-lgd.json | 清收尚未结束，可否锁定 LGD？ | 回收现值为 60，观察 LGD 为 .4；final_lgd 必须为空。补齐未来回收、成本、时间假设及清收状态，不能把暂时未回收全当最终损失。 | 清收团队、信用风险 |
| C01 / ead-utilization.json | 未使用额度会带来多少敞口？ | 60 + .5 × 40 = 80。把 CCF 从 .5 改到 1，EAD 应变为 100；CCF 是假设，需另行估计和压力评估。 | 授信团队 |
| C02 / ecl.json | 未来各年 PD 如何形成损失？ | 先按存活概率算边际 PD，再核对 EAD、LGD 和折现。缩短违约窗口不等于截断违约后的全部现金损失。 | 财务、减值模型负责人 |
| C02 / weighted-ecl.json | 情景权重变化如何影响汇总？ | .75 × 100 + .25 × 300 = 150；先统一日期、期限和口径，不能平均不同币种。 | 财务、模型负责人 |
| C02 / ecl-movement.json | 减值从 1047.619 增至 4905.995，原因是什么？ | 查看固定顺序的 exposure → default_window → parameters → weights 桥接。首尾核对且保留浮点残差；归因顺序会改变分项，不能把它说成独立因果贡献。SICR 需另外依政策和证据判断。 | 财务审阅者、信用风险 |
| M01 / market-stress.json | VaR 没有超限，是否安全？ | 示例 VaR 20、ES 26.6667，尾部包含 1.5 个观察的概率质量。另看命名压力损失；压力情景不当历史观察、不赋予未经支持的概率。 | 市场风险、交易台负责人 |
| C03 / counterparty.json | 有抵押为何仍有对手风险？ | EE [5,20]、PFE [10,30]、独立违约假设下 CVA 1.87。降低延迟收到的抵押再运行；法律净额结算与抵押可用性先核实，WWR 另行压力测试。 | CCR、抵押运营、法律 |
| B01 / broker-margin.json | 应追保多少，能回收多少现金？ | 基准借贷价值 110，压力后 64；贷款 120，追保要求 56，但变现现金 70、现金缺口 50。不得把追保要求当现金流入；调查集中发行人、停牌和变现时间。 | 融资风控、信用审批、运营 |
| B01 / concentration.json | 看似很多证券，是否真正分散？ | 先按关联发行人汇总再算 HHI。增加同一发行人证券数量不会改善经济集中度；明确分母及暴露口径。 | 信用审批、组合风险 |
| L01 / liquidity.json | 资产足够，为何无法按期支付？ | 查看第一个期末现金负值日；修改流入延迟和实际可用变现款再跑。按币种及实体另建请求，不能假设集团现金即时互通。 | 财资、流动性风险 |
| L02 / alm-nmd.json | 存款 beta/runoff 如何影响 EVE 和 NII？ | 基础行为 ΔEVE -28373.46、ΔNII -2700；更高 beta 分别 -40709.05、-7200。逐年本金归零并回收 900000。固定息资产和年末 runoff 假设下，快 runoff 不改变第一年 NII；不要强行让 EVE/NII 反向。 | ALM、财资、独立验证 |
| L02 / rates.json | 折现变化能否解释估值差异？ | 零冲击应无变化；固定正现金流与带负腿净现金流的方向可不同。本模块只是固定现金流折现，不代表全银行风险。 | 估值控制、ALM |
| G01 / monitoring.json | PSI 上升是否立即重训？ | 固定分箱保留两端尾部，明确平滑和人工阈值。先定位数据、客群及标签变化，再决定调查、限制或重训；未提供成熟损失标签时绩效仍未评估。 | 模型负责人、独立验证 |
| F01 / alert-capacity.json | 告警积压时如何分配审核能力？ | 按显式阈值和容量排序；区分排队、低于阈值、未知标签。精确率和成本只针对已知标签，不能推断真实犯罪或总体漏报率。 | 调查主管、合规 |
| A01 / ai-review.json | AI 报告能否交付？ | 分开核对数值、必要来源、人工语义判断、动作权限。全通过也只进入人工审阅；来源存在不能证明陈述真实。本工具不调用 AI、不执行交易。 | 报告负责人、模型治理 |

## 复用已有作品的完整任务

- **M02 估值与 Greeks**：从 [Model Risk Lab](https://github.com/zheyuliu328/model-risk-lab) 的公开欧洲式 FX 示例起步，固定报价方向、估值时间及利率约定；比较解析值和独立有限差分，改变 bump 大小并解释误差。输出价格/敏感度对比、约定清单与待审问题。复杂期权和专有 SIMM 参数不在这里声称实现。
- **O01 数据交付控制**：在 [Financial Control Tower](https://github.com/zheyuliu328/financial-control-tower) 用自行构造的两张表，加入重复 key、缺失行、抵消差异和单位变更；导出逐行差异。总数相同不作为通过依据。由数据负责人处理来源问题，分析人重跑并保留版本。
- **C02/G01 模型选择**：在 [Forecast Review Workbench](https://github.com/zheyuliu328/forecast-review-workbench) 统一样本、时间窗口和候选模型口径；保留失败候选、未解决问题及审阅意见。用 [Model Risk Lab](https://github.com/zheyuliu328/model-risk-lab) 挑战数值稳定性和敏感度。不要把拟合优度当选模结论。

上述链接基于目录中的公开版本检查；本次新增包的测试不等于重新验证所有独立项目。

## 每次练习必须留下的五项证据

1. **决策与边界**：今天要支持哪个决定，哪些决定没有授权，负责人员是谁。
2. **输入契约**：来源、日期、单位、粒度、缺失与排除项，哪些参数纯属假设。
3. **基准与反例**：先手算一个小样本；再改变一个关键假设，解释方向及不变项。
4. **残余问题与行动**：区分数据问题、模型局限、政策待确认；提出暂停、限制、补数据或重新验证的理由。
5. **复核与签核**：另一人能重跑并质疑结果；通过计算不替代业务和模型审批。

第一次练习保留基准报告；第二次必须修改输入形成不利情景；第三次不看答案解释结果。只有完成这三步，才将个人学习进度由“未评估”更新为“能复现/能挑战”，不能自动写成工作经验。
