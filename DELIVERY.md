# Delivery requirements

Objective: package the existing open-source projects into a coherent portfolio of realistic risk-work scenarios, executable methods and response plans; prioritize public showcases and build an honest learning/interview route for unfamiliar risk areas.

## Evidence required before completion

- Inventory every currently public repository in the supplied GitHub account, separating original projects, team work, forks and the profile. Rank showcase and learning priorities separately with explicit reasons.
- Provide a unified visitor route from work problem to method, usable project, worked example and evidence. Reflect current published versions rather than old audit summaries.
- Cover core credit, market, counterparty, liquidity, interest-rate, model-governance, data/operational, financial-crime and AI risk scenarios; identify additional specialist areas and prerequisites rather than asserting universal competence.
- Each core scenario needs a decision question, target role, input/units/source contract, model or control method, execution sequence, failure modes, response options, escalation owner, outputs and limitations.
- Supply independently invented worked examples for new numerical modules, runnable entry points, independent hand-calculation/identity checks and edge-case validation. Link existing tools for already implemented workflows.
- Provide role-based learning routes, explanation exercises, unfamiliar case questions, answer rubrics and honest authorship/experience wording. Personal mastery remains unassessed until the user demonstrates it.
- Validate repository navigation, case inventory, executable examples, output preservation and the published portfolio against its stated scope. Preserve source material and existing repositories.
- Publish reviewed public material and update the profile/local index to the unified entry; verify exact remote contents after publication.

## Continuing development, separate from this package delivery

Use actual reviewer feedback and the user's completed exercises to select deeper implementations. Full bank IRRBB, policy-specific SICR, joint wrong-way risk, production monitoring, source-system integration and the eight specialist areas remain explicit development/learning gaps. The package provides a route to discover and address these gaps; it does not claim to eliminate every possible unfamiliar risk topic or replace work experience.
